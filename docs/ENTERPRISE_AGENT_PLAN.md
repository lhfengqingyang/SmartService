# SmartService 企业化升级方案

**状态：规划中。** 本文描述在现有求职演示 MVP 上可逐步验证的工程能力，不表示项目已达到生产级要求。现有技术栈保持 FastAPI、smolagents、PostgreSQL/pgvector 和智谱接口。

## 现有基础

- 知识入库、Embedding、带来源的 RAG、按文档元数据执行的 ACL 检索。
- 订单查询、退款资格检查、只读退款准备工具；显式确认后由确定性业务代码创建模拟申请，并有幂等键与数据库约束。
- 固定 RAG/Agent 案例、运行指标、反馈审核队列和 PostgreSQL 集成测试。

## 优先级 1：Agent 质量评判与回归门禁

现有评测器能检查检索来源、引用格式、工具名称、参数与待确认动作，但缺少稳定的事实正确性标签、故障归因和基于阈值的发布决策。

1. 固定知识和订单快照，分开统计模型可用率、检索召回、片段命中、引用事实正确性、拒答、工具选择、参数正确性及越权调用。
2. 给案例补充人工审核的预期事实与禁用行为；逐例标记检索、生成、工具、业务规则或上游服务故障。LLM Judge 如使用，只作辅助，需用人工样本校准，不能代替业务真值。
3. 同一批案例比较变更前后结果；阻断新越权、误写和已通过案例的关键回退。真实模型调用失败单列可用性指标，不混入回答质量分母。

**验收：** 固定样本可重跑，报告同时列出可用性、质量、安全性和人工复核结果；至少一次真实改动的前后对比可解释。

## 优先级 2：工具治理与 MCP 适配

现有订单、退款工具在进程内直接调用业务函数，尚无 MCP 客户端或服务器。

1. 保留现有业务函数作为业务真值层；为工具定义稳定的输入/输出 Schema、读写等级、允许场景、超时、脱敏审计字段与错误分类。
2. 先将只读订单查询和退款资格检查暴露为一个独立 MCP 工具服务，Agent 通过明确允许列表发现及调用；服务端继续校验输入和业务权限。退款申请写操作仍走现有结构化确认分支，不让模型直接获得写工具。
3. 用协议兼容性和故障注入测试验证工具发现、调用、无效参数、权限拒绝、超时与断连。以实际选定的稳定 MCP 规范版本和 Python SDK 为准，不依赖草案行为。

**验收：** 同一业务函数可通过本地工具与 MCP 工具调用得到一致结果；未授权工具不会进入模型可调用列表，协议异常不会绕过业务规则。

## 优先级 3：限流、熔断与可观测性

1. 对模型和远程工具分别设置并发上限、单次超时、总预算与有限重试；仅对可安全重试的操作退避，尊重提供方限流信号，不对退款写操作自动重试。
2. 对持续 429、超时或远程工具故障设置可恢复的熔断状态；半开探测恢复后再放量。限流与熔断范围按模型/工具隔离，不阻断本地健康检查和确定性业务查询。
3. 用请求 ID 串联模型、检索、工具及业务结果；只记录耗时、状态、错误码与脱敏参数。修正 LLM 失败时 `retrieved_count=0` 的指标失真。

**验收：** 并发压测与故障注入下，请求按预算失败；429 不触发重试风暴；恢复后自动重新放量；可按请求 ID 定位失败阶段。

## 集成前提：复用真实登录态并持久化关键状态

企业环境由已有网关或登录系统验证身份；Agent 接收已验证的用户、租户和角色，而不是直接相信请求体中的同名字段。当前 MVP 尚无此集成，故不能声称租户隔离已具备真实鉴权。

当前 `ConversationStore` 是进程内字典。若要多实例运行，将会话归属、待确认动作、过期时间与版本号持久化到 PostgreSQL；并发确认与取消采用事务性终态控制，重复确认最多生成一份模拟申请。

## 简历表述边界

现在可写“实现 RAG、受控工具调用、模拟退款确认及评测闭环”。完成并验证上述各项后，再写“MCP 工具适配、可量化质量门禁、限流熔断和跨请求追踪”。真实身份集成和跨实例状态仍是上线前提，不能将现有 MVP 称为已上线的企业级 Agent 平台。
