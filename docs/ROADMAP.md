# 开发路线图

## 阶段 0：环境检查与项目初始化

**目标**：确认开发环境，建立项目结构和文档。

**任务**：
- 检查 Python、Git、Docker 环境
- 初始化 Git 仓库
- 创建项目目录结构
- 创建项目文档（AGENTS.md、PROJECT_STATUS.md、ROADMAP.md、API_CONTRACTS.md）
- 创建配置文件（.gitignore、.env.example、pyproject.toml）

**验收标准**：
- [x] 所有环境工具已检查并记录版本
- [x] 项目目录结构已创建
- [x] 四份核心文档已创建
- [x] 配置文件已创建，无真实密钥泄露
- [x] Docker Desktop、Docker Engine 和 Docker Compose 可用

**阶段间依赖**：无

---

## 阶段 1：数据库与服务骨架

**目标**：启动 PostgreSQL + pgvector，创建 schema 和基础表，完成 FastAPI 健康检查接口。

**任务**：
- 编写 docker-compose.yml 启动 PostgreSQL 16 + pgvector
- 创建 `ai` 和 `biz` schema
- 建立必要的数据表（知识库文档表、文档片段表、订单表、退款申请表）
- 实现 FastAPI 应用入口、`/health` 存活检查和 `/health/db` 数据库就绪检查
- 安装并验证核心依赖（smolagents、SQLAlchemy、psycopg、pgvector）
- 验证服务能够启动并连接数据库

**验收标准**：
- [x] Docker Compose 能启动 PostgreSQL + pgvector
- [x] `ai` 和 `biz` schema 已创建
- [x] 数据表已建立
- [x] FastAPI 服务能启动，`/health` 返回 200
- [x] `/health/db` 能确认服务连接数据库、pgvector 扩展和基础表已就绪

**阶段间依赖**：需要 Docker 已安装

---

## 阶段 2：知识库导入

**目标**：实现文档上传、解析、分块、Embedding 和存储。

**任务**：
- 实现 Markdown/TXT 文件上传接口
- 实现文本解析和分块逻辑
- 集成 Embedding 模型/API，实现真实向量化
- 将文档、片段及向量写入 PostgreSQL（ai schema）
- 实现异常处理和文件校验

**验收标准**：
- [x] 可上传 Markdown/TXT 文件
- [x] 文件被正确解析和分块
- [x] Embedding 生成真实向量（非随机）
- [x] 数据持久化到 PostgreSQL
- [x] 文件类型、大小校验生效
- [x] 路径穿越攻击被阻止

**阶段间依赖**：阶段 1 完成

---

## 阶段 3：RAG 问答

**目标**：实现基于知识库检索的问答功能。

**任务**：
- [x] 实现 Top-K 向量检索（含数据库内 ACL 过滤）
- [x] 调用 GLM-4.7-Flash 生成答案
- [x] 返回答案、来源和检索信息
- [x] 处理无证据和低相关度场景

**验收标准**：
- [x] 向量检索返回相关文档片段
- [x] LLM 生成的答案包含知识来源
- [x] 无证据时明确说明无法确定
- [x] 低相关度时给出提示

**阶段间依赖**：阶段 2 完成

---

## 阶段 4：业务接口

**目标**：实现订单查询、退款资格检查和模拟退款申请。

**任务**：
- 实现模拟订单数据和查询接口
- 实现退款资格检查逻辑
- 实现模拟退款申请创建和查询
- 加入参数校验、业务异常、幂等处理
- 编写自动化测试

**验收标准**：
- [x] 订单查询接口正常工作
- [x] 退款资格检查逻辑正确
- [x] 退款申请创建有确认边界
- [x] 幂等机制生效
- [x] 自动化测试通过

**阶段间依赖**：阶段 1 完成

---

## 阶段 5：smolagents 工具编排

**目标**：将业务接口封装为 Agent 工具，实现智能客服对话。

**任务**：
- 将订单查询封装为 Agent 工具
- 将退款资格检查封装为 Agent 工具
- 实现多轮对话和工具调用编排
- 明确退款创建的确认边界
- 验证工具调用结果来自真实业务逻辑

**验收标准**：
- [x] Agent 能正确调用订单查询工具
- [x] Agent 能正确调用退款资格检查工具
- [x] 退款创建需用户确认
- [x] 工具调用结果与直接调用业务接口一致
- [x] smolagents 与 GLM-4.7-Flash 兼容性已验证
- [x] 退款待确认动作使用结构化会话状态，不依赖自然语言历史执行
- [x] Agent API 具有端到端等待超时

**阶段间依赖**：阶段 3、阶段 4 完成

---

## 阶段 6：集成测试与交付

**目标**：验证完整流程，补充测试，完善文档。

**任务**：
- 验证知识库导入 → RAG 问答完整流程
- 验证订单查询 → 退款检查完整流程
- 补充自动化测试
- 完善 Swagger API 文档
- 编写 README 和启动步骤
- 提供演示数据与演示流程
- 安全检查
- 实现知识库文档列表与所有者删除
- 提供可重复的演示数据重置方式
- 建立固定 RAG/Agent 种子样本和离线评分器，为后续质量基线提供输入
- 记录 RAG 请求的状态、耗时、检索命中数与分数分布，用于排查线上检索质量
- 建立按回答 ID 回流的显式反馈，并提供可按组分析的轻量检索阈值实验
- 从用户主动提交原问题的无用反馈生成私有候选，经人工审核后加入固定回归评测集
- 对同一固定样本的改动前后报告比较可用性与成对质量指标
- 人工复核演示种子样本的事实标签、片段来源和已保存回答
- 以幂等离线任务同步负反馈到待标注队列，并记录审核决定
- 使用真实 PostgreSQL 和固定模型输出验收知识问答、反馈及模拟退款的 API 链路
- 在现有 smolagents 工具循环中增加跨知识库与订单的退款政策任务模式，保存必要的跨轮上下文，并对必要工具证据做服务端校验
- 可选：新增轻量客服前端，演示对话、来源、工具轨迹和结构化退款确认

**验收标准**：
- [ ] 完整端到端流程稳定运行（知识/RAG 与模拟退款准备/确认已在千问 3.7 Flash 下通过；跨知识/订单任务仍不稳定）
- [x] 自动化测试覆盖核心场景
- [x] 当前 12 条 MVP 路径均有成功响应模型，常见业务错误已在 OpenAPI 中列出
- [x] README 包含完整启动步骤
- [x] 无真实密钥泄露
- [x] 演示流程可复现
- [x] 固定种子样本可校验，离线评分器可对真实观测数据输出逐例报告
- [x] RAG 请求输出不含问题正文与用户标识的结构化运行指标
- [x] 成功 RAG 回答可提交反馈，检索阈值实验可稳定分组并记录实际阈值
- [x] 无用反馈可导出为私有候选，人工批准并补齐标签后可进入固定评测集
- [x] 前后报告可按同一案例比较可用性与自动检查得失，输出人工复核标记
- [x] 30 条演示样本已完成项目内部标签复核，16 条可回答 RAG 样本有片段级来源标签
- [x] 负反馈可幂等入待标注队列，审核后标记批准或驳回
- [x] 本地 PostgreSQL 集成测试走通知识/反馈队列与订单/退款确认链路，不依赖外部模型
- [x] 跨知识与订单任务模式的工具、上下文及结构化证据门禁通过本地自动化测试；千问 3.7 Flash 已有单个只读多工具真实样例通过，固定集与退款确认流程仍待联调
- [ ] 若实现前端，确认按钮只提交结构化授权，不由模型判断写操作授权

**阶段间依赖**：阶段 5 完成

## 阶段 7：企业化增强（阶段 6 验收后启动）

**目标**：在现有单体服务上补齐 Agent 质量门禁、MCP 工具适配、限流熔断与请求追踪；真实登录态及跨实例状态作为上线集成前提。具体范围和验收标准见 [ENTERPRISE_AGENT_PLAN.md](ENTERPRISE_AGENT_PLAN.md)。

**顺序**：质量评判与回归门禁 → 只读业务工具的 MCP 适配 → 模型与远程工具的限流熔断及追踪 → 真实身份和持久会话集成。

**当前状态**：质量门禁代码及固定案例已实现，20 条 RAG 子集真实复测通过；完整 Agent 评测仍因漏调必要工具而未通过。MCP、限流熔断及追踪未开始；不得将规划项计为已实现能力。
